# 0.2.3 查询恢复修复验证

日期：2026-10-26。先修复代码并完成测试，再更新本文与使用说明。本文仅描述源码与隔离测试，不包含真实账号、个人目录、凭据或录制活动。

## 修复行为

1. 已受限的账号不因重启自动试查。首次读取已保存的 Cookie 只建立基线；其后的真实登录或到期时间变化才推进会话版本。正常启动检查保留，暂停监听时的验证仍不直接启动录制。
2. 搜索失败后恢复原操作。服务保存交互操作 ID、关键词和主页用户 ID；重试优先恢复该搜索，通过 IPC 和快照将候选结果送回添加界面。指定目标重试仍检查该目标。

后台查询不覆盖交互操作。旧请求即使关键词相同，也不能完成新操作或丢失其身份过滤；登录变化触发的验证可继续尚未完成的搜索，并保持冷却及去重规则。

## 验证证据

- 首次凭据读取、已有目标和无已有目标的搜索重试、主页身份、目标检查并发及登录恢复回归测试，在修复前出现预期失败，修复后通过。
- 独立审查补出的同关键词旧请求抢占、持久化冷却期内首次搜索丢失恢复两项边界，同样先复现失败后修复；复核未发现其他直接相关阻塞问题。
- 完整自动测试 122 项通过：80 普通、42 Electron 原生。正常启动的目标检查、受限账号初始化、实际登录变化后的单次只读验证、暂停时不启动录制和冷却结束后恢复均有覆盖。
- 类型检查、ESLint、Biome 和生产构建通过。
- 桌面测试使用真实 Electron 主窗口、Vue、preload 与 IPC，模拟网站和签名。在修复前实际点击“重试”会查询旧目标；修复后，有／无已有目标时均查询原新主播并显示可添加候选。
- 专注观看、网页全屏及 Esc、最小化、托盘隐藏恢复、后台查询不导航观看页、诊断复制、移除确认和非法调用拒绝继续通过。扩展的界面测试固定随机源，保留生产环境 5 秒请求间隔下限。
