# 0.2.2 已知问题

2026-10-26 源码审查确认。以下五项均尚未修复，当前自动测试通过不代表这些边界通过。本文不包含真实账号、房间或个人目录。

## 启动可能自动试查受限账号

- 优先级：P2。
- 触发：已有监听目标，数据库保存访问限制、签名环境或接口结构阻止，重新启动应用。
- 行为：浏览器首次读取 Cookie 增加会话版本，服务将初始化当成会话变化，发起一次只读验证；即使监听暂停也会查询，成功后清除限制。
- 影响：不能把“已暂停”或已保存的限制当作启动后绝无网站请求的保证。隔离模拟已复现，未访问真实网站。
- 修复方向：区分首次凭据基线与后续真实变化，补持久化限制结合完整初始化顺序的测试。
- 代码：`apps/desktop/src/main/recorder-service.ts`、`apps/desktop/src/main/browser/browser-service.ts`。

## 搜索失败后的恢复未完成原搜索

- 优先级：P2。
- 触发：为添加新主播而搜索，失败后点击“重试”“修复并重试”或“验证后重试”。
- 行为：已有目标时可能优先检查旧目标；没有目标时虽重新搜索，但结果没有返回添加界面的候选列表。
- 临时处理：处理错误后再次使用搜索按钮，或重新从当前主页添加；核对返回的主播身份。
- 修复方向：保存原操作上下文并返回候选结果，覆盖失败搜索到恢复结果显示的完整路径。
- 代码：`apps/desktop/src/main/recorder-service.ts`、`apps/desktop/src/renderer/src/App.vue`。

## 关闭自动合并后缺少手动合并入口

- 优先级：P2。
- 触发：关闭自动合并，录制正常完成或手动停止后留下分片。
- 行为：任务保存为 `mergeState='none'`，界面只向 `pending` 状态提供“合并分片”；之后开启自动合并也不会改变旧任务。
- 影响：分片保留，但无法从界面将这类历史任务合并为成品。隔离目录及模拟媒体进程已复现。
- 临时处理：需要应用内自动生成成品时，在开始新任务前启用自动合并；已有分片继续保留。
- 修复方向：对有分片且未合并的任务提供手动入口。
- 代码：`packages/recorder-core/src/recording-engine.ts`、`apps/desktop/src/renderer/src/App.vue`。

## 旧磁盘检查可能误停同主播的新任务

- 优先级：P2。
- 触发：旧任务的异步磁盘检查等待期间，该任务结束，换盘并开始同主播的新任务；旧盘检查随后返回不可用。
- 行为：检查仅按主播 ID 停止任务，可能把新盘上的新任务停止并设为磁盘阻止。隔离目录及模拟媒体进程已复现。
- 临时处理：同主播换盘后若立即出现不符合新盘状态的磁盘阻止，确认目录可写和空间充足后手动恢复。
- 修复方向：探测返回后核对仍是同一次运行，再写阻止状态或停止。
- 代码：`packages/recorder-core/src/recording-engine.ts`。

## 历史列表与分片恢复限制为 500 条

- 优先级：P2，影响长期使用。
- 行为：“全部录制”只返回最近 500 条，启动分片扫描复用该查询，当前无分页入口。
- 影响：较早记录无法从界面访问；旧任务磁盘曾离线且缺少索引时，接回后也可能不再自动发现分片。文件本身不会因为数量上限被删除。
- 临时处理：保留原输出目录及备份，通过文件系统查找较早录像，不清理未合并的工作目录。
- 修复方向：界面增加分页，恢复扫描单独查询全部需要恢复的任务。
- 代码：`apps/desktop/src/main/store.ts`。
