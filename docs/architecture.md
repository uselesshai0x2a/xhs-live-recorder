# 桌面录制架构

## 边界

`packages/recorder-core` 提供目标、运行、设置等类型以及磁盘探测和录制引擎。通过仓储、媒体进程和磁盘接口工作，不依赖 Electron、JSON 配置或命令行启动流程。

`apps/desktop/src/main` 组装 SQLite 仓储、浏览器查询服务、串行调度、FFmpeg 进程、系统通知、托盘和生命周期。Vue 只通过 preload 暴露的窄接口操作；主进程校验调用来源必须是本地顶层界面，并验证参数。

两个 WebContentsView 共用 `persist:xhs-account`：前台显示原网站，后台执行网站自己的搜索页面。通过 CDP 按关键词、请求 ID 和查询实例关联 onebox 响应。请求观察只确认授权头存在，不持久化或重放签名。远程页没有应用 preload，禁用 Node，开启沙箱、上下文隔离和网页安全，仅允许官方 HTTPS 顶层地址。

## 查询与状态

每个目标独立计算下次检查时间：未开播目标在上次检查完成后 120 秒复查；直播中且有启动中、录制中或重连中的任务时，间隔为 300 秒。其余状态使用设置中的间隔（默认 120 秒）。调度每秒检查到期目标，请求始终串行，默认随机间隔 5–15 秒，下限可设置，上限为下限的 3 倍。手动查询共用队列，繁忙时顺延。

HTTP 461 使用 RESTRICTED 类型并持久化到账号状态，暂停自动查询，只允许用户新发起的试查成功后解除。429 至少退避 60 秒。授权 Cookie 变化或离开验证页只申请一次复查，只有有效业务响应才清除 AUTH 提示。错误按类别保存；成功清除账号级错误，不清除磁盘或手动停止阻止。查询受阻时显示最后明确状态及确认时间。

录制引擎在自然 EOF 或重试耗尽时发出一次流结束事件。服务按运行 ID 去重并保存待确认目标，等引擎完成收尾后进入串行队列；暂停时保留待确认项。手动停止、归档移除、退出和磁盘保护不会产生额外检查。确认下播立即推送界面，未知和错误响应不判下播。

确认候选用户 ID 后添加，后续结果必须匹配这个 ID，防止昵称重名误录。通知由 `live_sessions(targetId,roomId)` 去重。数据库中的用户手动停止、磁盘阻止、输出阻止各有独立原因。

录制启动在第一次异步操作前预占目标，防止同时检查/手动操作产生重复进程。任务标识由平台、用户 ID、房间 ID 派生；同房间可以有多个独立运行，每次 UUID、工作目录、重试分片名均独立。

## 存储与恢复

SQLite 包含 `settings`、`targets`、`tasks`、`runs`、`files`、`live_sessions`、`notices`、`account`。主进程同步短事务，WAL、外键、busy timeout 和 `user_version` 迁移，拒绝较新数据库版本。

版本 2 为目标增加归档时间、生命周期 generation、错误类别和最后明确确认时间。归档先禁止新工作再收尾任务，历史外键及分片保留；重新添加恢复同一目标并递增 generation。排队前、请求执行前及响应后校验 generation，数据库更新也拒绝旧代次写回，避免移除/重加与迟到响应互相覆盖。

录制使用源流复制，默认 30 分钟分片，可选转码。FFmpeg 隐藏启动，通过标准输入 `q` 温和停止，10 秒后强制终止。退出前取消新查询/新任务，收尾所有录制和合并，再关闭网页和数据库；退出期间保留分片，避免耗时合并。

磁盘探测使用 `statfs`，录制前、运行中、合并前都检查。合并临时文件放在本次工作目录，成功后重命名。清理仅针对本次已索引分片，失败保留文件。拔盘无法读取时保留已有索引，重启后重新核对实际存在状态。

## 发布

Windows NSIS x64 安装包包含 Electron、ABI 140 的 `better-sqlite3` 和 FFmpeg。原生模块从 asar 解包，FFmpeg 位于 resources。只打包桌面输出和依赖，不包含开发数据库、Session、录制样本或旧 CLI 配置。

尚未配置代码签名证书；签名和干净机器验收属于发布前待完成项。当前机器策略禁止运行未签名打包程序，开发入口仍可使用。
